🗂️ The Linux Filesystem — what lives where, and why

Linux has one tree starting at / (root). No C: drives. Every directory has a job — learn the jobs and you can walk into any server and find things.

/
The root. Everything hangs off this. You rarely put files here directly.
/etc
Configuration. Pronounced "etsy". Service configs live here: /etc/ssh/sshd_config, /etc/nginx/, /etc/hosts. Why here: one predictable place for every program's settings — editable text files, version-controllable.
/var
Variable data. Stuff that grows and changes: logs (/var/log/), mail spools, web roots (/var/www/). Why separate: a runaway log can fill a disk — admins often mount /var on its own partition so it can't take down /.
/home
People. Each user's personal directory: /home/admin/. Your dotfiles (.bashrc), scripts, notes. Root's home is the exception: /root/.
/opt
Optional add-on software. Third-party apps that don't come from the package manager — e.g. /opt/myapp/. Keeps vendor software out of system paths.
/bin · /sbin
Essential commands. /bin = everyone (ls, cat); /sbin = admin tools (iptables, reboot). Needed early at boot, before other filesystems mount.
/usr
User programs. The bulk of installed software: /usr/bin/, libraries in /usr/lib/. Read-only-ish in normal operation.
/tmp
Scratch space. Temporary files; typically wiped on reboot. Anyone can write here — which is exactly why you never trust files in it blindly.
/dev
Devices as files. Disks (/dev/sda), terminals, /dev/null (the void). Linux's big idea: everything is a file.
/proc · /sys
Fake files, real kernel. Not on disk — generated live. /proc/cpuinfo, /proc/meminfo: read system state by catting files.
🔍 LOGIC CHECK
A web app is crashing and you need its error log. Where do you look first? /var/log/ — because logs are variable data, and that is the one address every Linux admin memorizes. Config problem instead? /etc/<appname>/. Two directories solve half of all "where is it?" questions.
TRY IT NOWIn the Terminal tab: ls / → ls /etc → cat /etc/hosts → ls -lt /var/log. The -t flag sorts by time — newest first — which is how you find today's log.

🔐 Permission Math — rwx → octal, step by step

Every file has three audiences (owner, group, others) and three powers (read, write, execute). Click the boxes — watch the octal number update live.

Read (4)
Write (2)
Execute (1)

Octal: 644 rw-r--r--

THE MATHr = 4, w = 2, x = 1. Add them per audience: rwx = 4+2+1 = 7, rw- = 4+2 = 6, r-- = 4, --x = 1, --- = 0. Three audiences → three digits. 755 = owner rwx (7), group r-x (5), others r-x (5).
🔍 LOGIC CHECK
Files vs directories: on a file, x = "allowed to run as a program". On a directory, x = "allowed to enter / list through it". That's why directories are usually 755 and data files 644: everyone may read and pass through, but only the owner may change or execute.

🏁 Challenges

Prove the skills in the live terminal. Each challenge verifies your actual commands — no multiple choice.

0 of 3 complete

① Find the log file

Objective: in /var/log, find the most recently modified log and show its last 3 lines.
Tools: ls -lt (sort by time), tail -3.
Why: "something broke at 2am" → newest log first is the universal triage move.

② Fix the script permissions

Objective: /home/admin/deploy.sh won't execute (permission denied). Make it executable for the owner — and no more permissive than needed.
Tools: ls -l, chmod.
Why: the single most common "why won't my script run" fix in infrastructure work.

③ Timed navigation drill

Objective: beat the clock. Press Start, then in the terminal complete this route:
cd /etc → cd /var/log → cd /home/admin → cd /opt
Why: assessments are timed. Navigation must be reflex, not recall.
